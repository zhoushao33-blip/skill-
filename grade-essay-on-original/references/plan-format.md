# 批注计划与制稿规则

## 运行

使用 Python 与 PyMuPDF。图片文件会在内存中转换为保留照片内容的PDF，不改写源文件。

```bash
python3 scripts/render_print.py prepare --out-dir /absolute/work/prepared /absolute/input.pdf /absolute/photo.jpg
python3 scripts/render_print.py render /absolute/work/plan.json --out-dir /absolute/work/print
```

prepare 生成页图和尺寸/哈希清单。页图为 1.5 倍源PDF坐标；从该页图读出的像素坐标除以 1.5，得到批注计划中的坐标。源PDF单位为点，原点左上，x向右、y向下。不能混用页图像素与源PDF点坐标。读图工具如果再次缩放显示，应以图像实际尺寸换算。

render 使用输入 plan 中的当前文件，输出 `print.pdf`、逐页PNG预览、映射记录及本轮计划副本；不会自动判断作文正误，也不会调用阿里。按批量来源分别执行 render，避免文件合并后无法区分班级或日期。

## 最小计划格式

```json
{
  "title": "初三英语作文 · 原图批改建议",
  "provider_status": "直接原图审阅；外部调用0次",
  "sources": [{"id": "s1", "path": "/absolute/input.pdf"}],
  "essays": [{
    "source": "s1",
    "page": 1,
    "label": "原第1页",
    "crop": [0, 0, 612, 792],
    "regions": [[0, 0, 612, 404], [0, 388, 612, 792]],
    "notes": [{
      "type": "error",
      "old": "原图实际保留写法",
      "new": "建议改法",
      "reason": "简短中文理由",
      "boxes": [[100, 120, 180, 140]]
    }]
  }]
}
```

- `page` 从1计数，源文件ID必须唯一。一篇跨页时保留真实页序；同篇编号可由最终代理检查和保持连续。
- `type` 只能为 `error`、`optional`、`check`。
- `notes` 必须按原文阅读顺序排列；脚本依次编号。倾斜页同一行的y值可能不同，不可机械按y精确排序后破坏左右顺序。
- `boxes` 可记录跨行同一个问题的多段范围，但不同修改点必须拆成不同 note。插入点可以用紧邻实际缺失位置的小矩形表示，不要用不存在的原句假装学生写过。
- 每个范围必须实际渲染为透明矩形框：`error` 红实线框、`optional` 红虚线框、`check` 灰框。必须把对应词句框起来，不能退化成下划线；跨行分段画框，编号放在附近空白处。
- `crop` 只裁无关空白，必须保留所有正文；`regions` 有序覆盖正文，可以小范围重叠。不要把正文从分区之间漏掉。
- `layout: "wide"` 可对很小的手写字使用全宽原图、下方双栏批注。该布局宜用较短的原图分区。默认是 `left-right`。
- 相同分区批注过多时脚本自动重复原图并分页；若原图仍过小，调整分区或 wide 布局，不要单纯缩小字体。
- 原件另存；视觉相似不能证明原件字节相同，重复扫描需看图判断并保留原页映射。

## 复核重点

手写判断需要语境：`a` 是否真的漏写、`s` 是否确实不存在、代词回指对象、两个活动是独立项目还是一个整体、书写相连还是缺空格，都不能仅凭OCR或模板规则确定。改动必须回到原图确认，仍不清楚就待核对。

可选润色只表达选择，不改写成“原句错误”。对意思和数量不明的句子提供条件式建议，避免替学生决定想表达什么。不要从旧作文批注复制到新学生。
